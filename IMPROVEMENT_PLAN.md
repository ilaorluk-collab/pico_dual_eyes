## 2. DMA для SPI (критичный апгрейд)

**Проблема:** Сейчас `spi_write_blocking()` крутит CPU в пустую пока байты уходят по SPI. Каждый кадр = 115200 байт × 2 дисплея. На 25MHz это ~9.2мс на дисплей, причём CPU ничем другим не занят.

**Решение:** Использовать DMA каналы RP2040:
- DMA channel 0 → SPI0 TX (левый дисплей)
- DMA channel 1 → SPI1 TX (правый дисплей)
- Оба канала запускаются одновременно — два дисплея обновляются параллельно за те же ~9.2мс вместо ~18.4мс последовательно
- CPU свободен пока DMA работает — можно распаковывать следующий кадр

**Что нужно:**
- Подключить `hardware_dma` в CMakeLists.txt
- Настроить 2 DMA канала: source = frame_buf, dest = spi_get_hw(spiX)->dr, transfer_count = RAW_FRAME_SIZE/4 (32-bit transfers)
- Использовать `dma_channel_wait_for_finish_blocking()` или прерывание

**Ожидаемый результат:** FPS вырастет с текущих ~12 до ~25-30.

## 3. Double Buffering

**Проблема:** Один `frame_buf[115200]`. Пока кадр отправляется — нельзя готовить следующий.

**Решение:** Два буфера `frame_buf_a` и `frame_buf_b`:
- Пока DMA отправляет буфер A — `unpack_1bit_to_rgb565()` заполняет буфер B
- По завершении DMA — swap указателей
- Память: +115200 байт RAM. У RP2040 264KB, текущее использование ~115KB — влезет с запасом

**В связке с DMA:** Это даст конвейер: распаковка || отправка, вместо распаковка -> отправка.

## 5. PWM Подсветка

**Текущее:** GPIO pin 22, просто on/off.
**Решение:** Использовать hardware PWM:
- Слайс PWM подключён к GPIO 22 (slice 3, channel A)
- Частота ~1kHz, duty cycle 0-100%
- Fade-in при старте: плавное нарастание яркости за 0.5-1 сек
- Fade-out/fade-in между анимациями для плавных переходов
- Ночной режим: пониженная яркость

```c
gpio_set_function(TFT_BLK, GPIO_FUNC_PWM);
uint slice = pwm_gpio_to_slice_num(TFT_BLK);
pwm_set_wrap(slice, 255);
pwm_set_chan_level(slice, PWM_CHAN_A, 255); // яркость 0-255
pwm_set_enabled(slice, true);
```

## 6. RLE Компрессия фреймов

**Проблема:** Каждый фрейм 7200 байт (1-bit, 240x240). 91 фрейм x 7200 = 655KB. На RP2040 всего 2MB флеша.

**Решение:** Run-Length Encoding:
- Кодировать серии одинаковых бит: `[бит][длина]`
- Фон Бендера (чёрный) — огромные серии нулей, сжимается очень хорошо
- Типичный 1-bit фрейм сжимается в 2-5 раз
- Декодер на C: простой цикл, читает бит + длину, заполняет output

**Изменения:**
- Скрипт `generate_anim_data.py` — добавить RLE компрессию
- `unpack.h` — заменить `unpack_1bit_to_rgb565()` на `unpack_rle_to_rgb565()`
- Формат: `[uint8_t bit_count][uint8_t value][uint16_t repeat]` или проще — побитовый RLE

**Ожидаемый результат:** 655KB -> ~130-300KB, освободится ~350KB флеша для новых анимаций.

## 7. USB Команды (Serial управление)

Уже есть `pico_enable_stdio_usb(1)` — можно читать команды через `getchar()`:

```
Команды (отправлять через терминал/serial):
  0-4     — воспроизвести анимацию по индексу
  +       — увеличить яркость
  -       — уменьшить яркость
  s       — остановить/возобновить
  r       — случайная анимация
  i       — инфо (текущая анимация, FPS, uptime)
  p       — пауза
```

**Реализация:** Неблокирующее чтение через `stdio_usb` + проверка в основном цикле. Не блокирует анимацию.

## 8. Многоцветная палитра

**Текущее:** 1-bit — 1 = жёлтый, 0 = чёрный.

**Решение:** Расширить до 2-bit (4 цвета) или 4-bit (16 цветов):
- 2-bit: `COLOR_BLACK`, `COLOR_YELLOW`, `COLOR_WHITE`, `COLOR_DARK_YELLOW`
- Это даст белый для зубов/глаз Бендера и тёмно-жёлтый для теней
- Размер фрейма: 2-bit = 14400 байт (в 2 раза больше), 4-bit = 28800
- Но с RLE компрессией разница нивелируется

**Скрипты:** Обновить `convert_to_raw.py` для генерации multi-bit фреймов с палитрой.

## 9. PIO Аудио — Bender Voice

**Идея:** Использовать PIO + PWM для воспроизведения звука через пьезо-динамик:
- Хранить короткие аудиосэмплы в флеше (ADPCM, 8kHz mono)
- Bender фразы: "Bite my shiny metal ass!", "Kill all humans!", "I'm back baby!"
- PIO state machine генерирует PWM на GPIO пине
- Можно подключить через транзистор к небольшому динамику

**Аппаратное:** 1 GPIO + пьезо или мини-динамик + NPN транзистор + резистор.

---

## 10. IR Датчик присутствия

**Идея:** Подключить HC-SR04 (ультразвуковой) или IR датчик:
- Когда никого нет → глаза закрыты / спящий режим (чёрный экран, подсветка 0%)
- Человек приближается → wakeup анимация → основной цикл
- Человек уходит → fade out → sleep
- Экономит батарею если портативное устройство

**Пины:** HC-SR04 нужен 2 GPIO (trig + echo).

---

## 11. Сервы — физическое движение глаз

**Идея:** Два микро-сервы SG90 поворачивают дисплеи:
- Глаза смотрят влево/вправо/центр
- Синхронизация с анимацией: при "orbit" — глаза поворачиваются
- Плавное перемещение через PWM серво
- Нужен внешний 5V питание для серв (RP2040 не тянет)

**Пины:** 2 GPIO для PWM серво.

---

## 12. Дополнительные анимации

Новые идеи для фреймов:
- `angry` — красные глаза, прищур
- `love` — сердечки вместо зрачков
- `confused` — глаза в разные стороны
- `wink` — один глаз закрыт
- `scan` — сканирующая линия как у терминатора
- `glitch` — глитч-эффект, битые пиксели
- `sleep` — медленное закрывание глаз
